# ATT&CK: закреплённый источник и проверенная разметка

Проект использует официальный **Enterprise ATT&CK v20.0**, представленный в **STIX 2.1**. Источник — [mitre-attack/attack-stix-data](https://github.com/mitre-attack/attack-stix-data), полный commit `20664a889568dce884a1dac0ec7b12ae3a199f51`, полученный при разрешении тега `v20.0`.

[Метаданные каталога](../profiles/attack/metadata.json) сохраняют tag object, commit, URL исходного bundle, его размер и SHA256, а также checksum производного snapshot. В репозитории хранится компактный каталог: 867 техник/подтехник, 15 канонических тактик, их lifecycle flags, связи родителей и официальные связи замены. Полный STIX bundle при обычной проверке не нужен.

## Что проверяется

```bash
.venv/bin/python tools/check_attack.py check
```

Команда не обращается к сети. Она сначала проверяет checksum и provenance каталога, затем проверяет технику и тактику каждого DetCard и Sigma-правила.

- Неизвестные, revoked/deprecated идентификаторы активных артефактов считаются ошибками.
- У deprecated-артефактов исторические ссылки остаются видимыми как предупреждения.
- Дополнительная каноническая тактика, не назначенная выбранной технике, вызывает предупреждение о контексте.
- Отношение родителя и подтехники учитывается; разные подтехники не считаются эквивалентными.
- Sigma может использовать канонические tactic shortnames с `-` или `_`, а также TA ID. Group/software/campaign/mitigation/data-source/data-component namespaces не проверяются как тактики.

Успешный lint подтверждает согласованность разметки с выбранной версией каталога. Он не устанавливает истинность события атаки и не измеряет качество детекции.

## Linux log clearing: официальная замена

В исходном v20.0 объект **T1070.002 — Clear Linux or Mac System Logs** имеет `revoked: true` и официальную связь `revoked-by` с **T1685.006 — Clear Linux or Mac System Logs**. У нового объекта `revoked: false`; смысл описания сохраняется: очистка системных журналов Linux/macOS, в том числе в `/var/log/`, для сокрытия следов.

После проверки описания первичная разметка Linux Sigma и карточки перенесена на **T1685.006**, тактика — **defense-impairment (TA0112)**. Это изменение опирается на явную связь источника, а не на поиск похожего названия.

Имя каталога `techniques/T1070_Indicator_Removal/` и ID `DET-LNX-T1070-LOGWIPE-003` сохранены намеренно: на них уже ссылаются packs, документация и тесты. Семантическую разметку задают поля `techniques`/`tactics` и Sigma-теги, а не подстрока исторического имени. Решение и версия источника отражены в changelog карточки.

## Тактики v20.0 и контекст

`defense-evasion` отсутствует в каноническом реестре тактик v20.0. Единой строковой замены для всех детектов нет: нужно использовать фазы конкретной техники.

| Выбранная техника | Канонические фазы v20.0, существенные для текущей разметки |
|---|---|
| T1070 / T1070.001 | stealth (TA0005) |
| T1685.006 | defense-impairment (TA0112) |
| T1490 | impact |
| T1550, включая T1550.002/.003 | lateral-movement |
| T1078 | initial-access, persistence, privilege-escalation, stealth |
| T1110 | credential-access |
| T1190 и T1505.003 | initial-access для T1190; persistence для T1505.003 |
| T1566 | initial-access |
| T1569.002 | execution |

Таблица поясняет разметку текущих правил; это не замена полному каталогу. Карточка выбирает фазы, соответствующие заявленному наблюдаемому поведению, и не обязана заявлять каждую фазу, возможную для семейства техники.

После review более широкий контекст вынесен из первичных тактик в примечания DetCard. Например, lateral movement после valid login, initial access после brute force, execution после phishing и persistence/lateral movement после service execution полезны аналитику, но не считаются дополнительной первичной разметкой этих техник. Контекст в примечаниях сохраняет смысл цепочки без завышения покрытия.

## Обновление и происхождение данных

Обновление выполняется отдельным изменением по [инструкции каталога](../profiles/attack/README.md): выбрать официальный tag/commit, получить bundle с сохранением TLS-проверки, проверить ожидаемый SHA256 и детерминированно сгенерировать snapshot. Затем нужно проверить новые revoked/deprecated ссылки, преемников, изменения фаз и соответствие поведения детектов. Автоматическая замена тегов для получения зелёного CI не используется.

Ссылка на полный commit закрепляет используемую ревизию. SHA256 обнаруживает изменение байтов относительно записанных метаданных; он не означает проверки цифровой подписи MITRE и не гарантирует неизменность upstream-тега. CI работает офлайн с выбранной версией, а не отслеживает ежедневно новые релизы ATT&CK.

Оригинальное уведомление об авторских правах из STIX и ссылка на условия использования сохранены в [NOTICE](../profiles/attack/NOTICE.txt). Проект не аффилирован с MITRE и не одобрен MITRE.
