# v0.3 — проверяемые детекты и Elasticsearch Basic

Черновик описания следующего релиза. Тег и GitHub Release ещё не созданы. Перед выпуском требуется опубликовать окончательный набор изменений и проверить CI именно на его commit; актуальные локальные результаты приведены в [отчёте](../validation_report.md).

Портфель правил дополнен исполняемыми сценариями и воспроизводимыми проверками. Для пилотов используется бесплатный Elasticsearch Basic, без trial и платных функций.

## Изменения

- Строгая проверка DetCards, ссылок и закреплённого MITRE ATT&CK v20.0; отдельные проверки Sigma-предикатов, YARA и Suricata PCAP replay.
- Нормализация Windows auth XML и Linux sshd journal; точные фиксированные и скользящие окна для поддержанного T1110-подмножества.
- Непрерывные Windows T1110 pipelines с immutable ingestion, SQLite checkpoints, transactional outbox, повторной доставкой и ограниченной обработкой поздних событий.
- Конечный Kerberos 4769 replay: успешные RC4-запросы, точная группировка requester/domain/IP и число разных service SID.
- Конечная host/web-корреляция по хосту, доверенной файловой области, пути и времени, со ссылками на исходные события.
- Конечный Sysmon 10 LSASS-пилот: точный бит `PROCESS_VM_READ`, GUID процессов, строгая нормализация XML v3 и отдельный профиль Basic. Широких исключений по имени AV/EDR нет.
- Конечная NewCredentials/4672-корреляция: точные host/boot/LogonId/SID, связанные события привилегий, симметричный допуск времени и отказ при неоднозначности. Легитимный `runas /netonly` остаётся кандидатом; PtH не объявляется подтверждённым.
- Исправление пропуска `-EncodedCommand` в Office-правиле и дополнительные проверки формы параметров. Воспроизводимые офлайн-замеры ограниченных rolling-v2 и LSASS вычислений с явными границами измерений.
- Отдельная группировка rolling-алертов в эпизоды и проверяемый экспорт evidence с сохранением исходных сигналов.
- Уточнённая атрибуция владельца в лицензии и карточках детектов.

## Границы выпуска

Карточки остаются в lifecycle `test`. Частичная проверка реализации не означает измеренную эксплуатационную точность. Реальные precision, TPR, FPR и latency пока не заявляются; легитимные совпадения присутствуют в ожидаемых результатах.

18 legacy Hunt остаются проектными описаниями. Отдельные host/web, LSASS и NewCredentials runtimes не исполняют общий join/first_seen DSL. Linux SSH работает офлайн; реальный Windows collector, нормализация native host/web источников и другие SIEM требуют отдельной проверки.

Для v1, rolling v2, Kerberos, host/web, LSASS и NewCredentials используются разные профили и, где применимо, отдельное состояние. Автоматическая миграция индексов или SQLite state не предусмотрена. Перед применением следует прочитать контракт выбранного сценария и ограничения bounded replay.

## Проверка перед выпуском

`make check` и `make check-elastic` проверяют текущие исходники. Для сетевых правил отдельно выполняется `make check-network`. В [validation report](../validation_report.md) различаются выполненные локальные проверки, результаты опубликованного CI и ограничения наблюдаемого поведения.
