# Первый проверяемый запуск

Нужны Python 3.12 и Make. Из корня репозитория:

```bash
make setup
make demo
```

`make setup` устанавливает зависимости по закреплённым хешам. Демонстрация
работает офлайн на включённых синтетических данных; Docker для неё не нужен.
Текст команд в fixtures обрабатывается как данные и не исполняется.
Демонстрация не создаёт индексов, не обращается к сети и не пишет файлы.

Ожидаемый JSON содержит `checks_passed: 7`. Каждый сценарий сверяет кандидата
и исходные события с объявленным ожиданием; ошибка в любом из сценариев
завершает команду ненулевым кодом без частичного отчёта об успехе.

| Сценарий | Что проверяется | Ожидаемые кандидаты |
|---|---|---:|
| `auth-v1` | Десять ошибок входа в одном фиксированном окне | 1 |
| `rolling-v2` | Десять ошибок через границу фиксированного окна; v1 на этих данных даёт 0 | 1 |
| `kerberos` | Успешные RC4 TGS к пяти различным сервисным SID | 1 |
| `host-web` | Запись файла и последующий запрос того же хоста/пространства/пути; один повтор доставки | 1 |
| `lsass` | Sysmon 10 XML с правом чтения памяти и похожее событие только с query-правом | 1 |
| `newcredentials` | Security 4624/4672 XML одной сессии с явной синтетической boot-областью | 1 |
| `process` | Sysmon 1 XML с regsvr32 remote-scriptlet текстом и обычный запуск Notepad | 1 |

Запустить один сценарий можно напрямую:

```bash
.venv/bin/python tools/demo.py --scenario process
```

Скрипт также работает вне каталога репозитория, если указать абсолютные пути
к интерпретатору и `tools/demo.py`.

## Проверка в бесплатном Elasticsearch Basic

Для нативных проверок дополнительно нужны Docker и Compose v2:

```bash
make lab-up
make check-elastic
make lab-down
```

Интеграционные тесты создают отдельные временные индексы и удаляют их после
проверки. Лаборатория привязана к loopback; `make lab-down` сохраняет её named
volume. Установка реального Windows collector в этот запуск не входит.
Полный набор проверок описан в [CONTRIBUTING](../CONTRIBUTING.md).

Для собственных экспортированных событий сначала выберите точный контракт:
[Windows process](windows-process.md), [LSASS](lsass.md),
[NewCredentials](newcredentials.md), [Kerberos](kerberos.md),
[host/web](correlation.md) или [Windows auth](elastic.md).
У Windows process-профиля есть явное ограничение ASCII для полей,
участвующих в Sigma-предикатах; неподдержанный вход отклоняется.

Совпадение означает кандидата в рамках выбранного наблюдаемого поведения.
Легитимная административная активность может совпадать. Эти семь демонстраций
не измеряют operational precision/TPR/FPR и не заменяют проверку всей библиотеки:
для неё выполняется `make check`, а сетевые правила отдельно проверяются
командой `make check-network`. Фактические результаты и границы проверки
собраны в [validation report](validation_report.md).
