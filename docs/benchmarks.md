# Ограниченный benchmark конечного replay

`tools/benchmark_replay.py` измеряет офлайн-вычисление двух детекторов на заданных
синтетических входах. Это воспроизводимый способ получить время и память для
конкретной версии кода. Результат не является production EPS, задержкой живого
сервиса или оценкой точности детектов.

## Запуск

Требуется Linux и установленное окружение `make setup`; Docker и сеть не нужны.
Быстрый профиль использует по три независимых процесса для 1000 и 10000 событий:

```bash
mkdir -p artifacts
.venv/bin/python tools/benchmark_replay.py --output artifacts/replay-benchmark.json
```

Для отдельного сравнения трёх размеров:

```bash
.venv/bin/python tools/benchmark_replay.py \
  --sizes 1000 10000 50000 --repeats 3 --seed 424242 \
  --output artifacts/replay-benchmark-extended.json
```

Существующий отчёт не перезаписывается. Для повторного измерения задайте новое
имя. Без `--output` JSON выводится в stdout. Профиль можно выбрать через
`--profiles rolling-v2` или `--profiles lsass`. CLI работает и вне каталога
репозитория при использовании абсолютного пути к скрипту.

Один sample ограничен 100000 событиями и 120 секундами; повторов — от 1 до 10,
размеров — не больше пяти. Суммарный вход всех samples ограничен 2000000 записей.
Нарушение лимита или ошибка детектора завершают весь запуск ошибкой. Успешный
частичный результат не выдаётся. Это ограничение объёма работы, не жёсткий лимит
выделяемой памяти процесса.

## Что подаётся на вход

| Профиль | Синтетический вход | Независимое ожидание |
|---|---|---|
| `rolling-v2` | Одно сочетание account/IP, события 4625 с разными timestamps через 1 ms; весь набор внутри окна 5m, штатный Hunt с порогом 10 | `max(0, N−9)` алертов; значения `fails` последовательно от 10 до N |
| `lsass` | Валидные GUID/пути/host identity, цель `lsass.exe`; каждая десятая запись содержит VM_READ, остальные — query-only. Среди совпадений есть AV-named source | `ceil(N/10)` алертов с заранее определёнными Event ID |

Порядок перемешивается воспроизводимо по `--seed`. Маски, имена и объёмы не
представляют измеренную рабочую популяцию. Разная плотность алертов — часть
сценария; значения двух профилей нельзя трактовать как соревнование реализаций.

Для каждого вызова детектора `max_events` и `max_alerts` задаются равными N.
Это намеренно позволяет dense rolling-набору создать больше стандартного
лимита 10000 алертов. Значения записаны в каждый sample; настройки обычных
runtime-команд не меняются.

## Границы измерения

- `replay_seconds` — только вызов детектора: валидация, dedup, сортировка,
  вычисление и создание алертов. Начальные импорты, генерация входа, подсчёт
  контрольных сумм и проверка результата происходят вне этого таймера.
- `child_process_seconds` — весь новый дочерний процесс, включая интерпретатор,
  импорты, генерацию, replay и проверки. Процесс для каждого sample новый;
  результаты одного worker не используются следующим.
- `peak_process_rss_kib` — Linux `ru_maxrss`, максимальный RSS всего worker в
  KiB. Он включает Python, импорты, входные объекты, промежуточные структуры,
  алерты и проверки. Это не дополнительная память одного detector call.
- `events_per_second` — N / время конечного detector call. Здесь нет стоимости
  collector, JSONL/XML ingestion, сети, Elasticsearch, SQLite, refresh, outbox,
  отправки алертов или накопленной истории.
- `empirical_p95_replay_seconds` — nearest-rank по выполненным samples. При
  доступных 1–10 повторах это максимум выборки; показатель не оценивает p95
  длительного сервиса и не задаёт SLO. Для сравнения видны все samples и median.

Каждый sample сверяет число/identity ожидаемых алертов или точные rolling counts.
Повторы должны иметь одинаковые SHA256 входа и выходных алертов. Изменение
исходников во время запуска отвергает смешанный отчёт. В JSON записаны Python,
платформа, логические CPU/affinity, Git HEAD/dirty flag, SHA256 релевантных
исходников, схемы, Hunt и dependency lock. Эти данные важны при сравнении двух
измерений; одинаковый Git HEAD при dirty tree не означает одинаковый код.

## Выполненный локальный запуск

2026-11-07 выполнена расширенная команда выше: два профиля, три размера,
по три отдельных процесса — **18 успешных samples**. Во всех повторах совпали
ожидаемые результаты и SHA256 входов/алертов; исходники во время замера
не менялись. Общие pytest-наборы завершились до запуска benchmark.

Среда: Python 3.12.14, Linux 6.18.57 x86_64, glibc 2.41;
процессу доступны 5 логических CPU. Samples выполнялись последовательно.
Это облачная среда без гарантии выделенных CPU. Замер относится к рабочему
дереву с изменениями поверх `dc0ba3f`, а точные SHA256 исходников сохранены
в отчёте.

| Профиль | События | Алерты | Медиана replay, с | Максимум replay, с | Максимальный RSS процесса, MiB |
|---|---:|---:|---:|---:|---:|
| rolling-v2 | 1 000 | 991 | 0.0260 | 0.0330 | 20.5 |
| rolling-v2 | 10 000 | 9 991 | 0.1907 | 0.1977 | 33.5 |
| rolling-v2 | 50 000 | 49 991 | 0.9256 | 0.9433 | 91.5 |
| LSASS | 1 000 | 100 | 0.0599 | 0.0612 | 20.1 |
| LSASS | 10 000 | 1 000 | 0.5798 | 0.7580 | 29.4 |
| LSASS | 50 000 | 5 000 | 3.0283 | 3.0326 | 70.6 |

Исходный локальный отчёт — `artifacts/replay-benchmark-extended.json`.
Его [сохранённая копия](data/replay-benchmark-2026-11-07.json) содержит все
18 samples, параметры, хеши и сведения о среде. RSS охватывает весь worker,
а время replay — только вызов детектора, как описано выше. Эти результаты
не измеряют NewCredentials, непрерывный pipeline или пропускную способность
Elasticsearch. Три повтора на трёх размерах не устанавливают предел
масштабирования и не подтверждают производственный SLO.

## Что остаётся проверить для эксплуатации

Этот benchmark не устраняет полные проходы по spool и сохранённой истории
эпизодов. Они остаются ограничениями текущей архитектуры. Следующий отдельный
эксперимент должен определить рабочий поток, размеры событий, долю совпадений,
длительность истории, доставку и стоимость native Basic. Нужны backlog catch-up,
память, реальные задержки, восстановление после остановки и нагрузка на диск.

Результаты фактически выполненных запусков должны храниться в `artifacts/` и
сопровождаться указанными параметрами и областью измерения. Наличие этого
инструмента само по себе не является результатом benchmark и не повышает
статус DetCards.
