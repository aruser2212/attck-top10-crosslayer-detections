# План проверки DET-WIN-T1547-RUN-KEY-ADD-001

Предикат: Запуск `reg.exe` с `add` точно указанного `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или соответствующего ключа в `HKLM`, с отдельными параметрами `/v` и `/d`. После каждого параметра требуется пробел/таб; значение параметра по этой строке не разбирается. Ключ может быть заключён в двойные кавычки.

Ожидания заданы вручную в [manifest](../../../tests/fixtures/sigma/predicates.json), suite `6d621830-6b1b-4eaa-ab18-a566c208174a`. Поле `match` относится к Sigma-предикату; `profile_valid` и `outcome` отдельно описывают контракт process-v1. Ни одна строка команды при тестировании не исполняется.

| Поддержанная форма команды | Кандидат с исходным event ID и process GUID |
| Регистр, ASCII-пробелы и табы в поддержанных позициях | Указанное в fixture совпадение |
| Авторизованная активность с теми же условиями | `benign_candidate`, совпадение сохраняется |

RunOnce, соседние ключи, HKEY_CURRENT_USER/HKEY_LOCAL_MACHINE, удалённый registry path, default-value `/ve`, PowerShell и прямые Registry API находятся вне покрытия. Строка не доказывает запись, существование исполняемого файла, запуск автозагрузки или повышение привилегий. Для подтверждения изменения нужны отдельные registry events.

Проверить `make check`, затем общий finite process-v1 replay на Elasticsearch Basic: маленькие страницы, точные ожидаемые rule/event IDs, immutable retry и XML → CLI. Native сравнение выполняется на одних входных записях; не заменять ручные ожидания результатом самого детектора. Лимит, неполное чтение или некорректный профиль должны завершать проход ошибкой.
