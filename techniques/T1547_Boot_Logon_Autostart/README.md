# T1547.001 — Registry Run Key Value Addition Command Candidate

Запуск `reg.exe` с `add` точно указанного `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или соответствующего ключа в `HKLM`, с отдельными параметрами `/v` и `/d`. После каждого параметра требуется пробел/таб; значение параметра по этой строке не разбирается. Ключ может быть заключён в двойные кавычки.

## Наблюдаемый смысл

Сигнал описывает процесс с указанным текстом команды. Он не подтверждает успешность операции или злонамеренность. Имя executable не удостоверяет происхождение бинарного файла.

Пример строкового входа fixture:

```text
reg.exe add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v ExampleApp /d C:\Tools\app.exe /f
```

## Источник и границы

Нативный путь использует Sysmon Event 1 версии 5 и строгий `process-v1`. Сохраняются host/process GUID, timestamp и исходная командная строка. Поля предиката должны быть ASCII; неподдержанный вход отклоняется явно. Пробелы и табы учитываются только в перечисленных формах. Это сопоставление сырого текста, а не разбор Windows argv: цитируемые упоминания и некорректные команды могут оставаться кандидатами, а варианты вне описанных форм могут не совпасть.

RunOnce, соседние ключи, HKEY_CURRENT_USER/HKEY_LOCAL_MACHINE, удалённый registry path, default-value `/ve`, PowerShell и прямые Registry API находятся вне покрытия. Строка не доказывает запись, существование исполняемого файла, запуск автозагрузки или повышение привилегий. Для подтверждения изменения нужны отдельные registry events.

## Легитимная активность и проверка

Установщик штатного приложения или администратор может добавить такой Run value. Ожидаемый benign match сохраняется без широкого исключения каталогов приложений.

Ручные ожидания хранятся в [общем Sigma manifest](../../tests/fixtures/sigma/predicates.json), rule ID `6d621830-6b1b-4eaa-ab18-a566c208174a`. Отсутствующее обязательное поле даёт Sigma nonmatch, но для строгого process-v1 считается ошибкой профиля; оно не является доказательством легитимной активности. Исполненные проверки приведены в [validation report](../../docs/validation_report.md).

Lifecycle — `test`, validation — `partial`, эксплуатационные TPR/FPR/latency не измерены. Общий Hunt DSL и непрерывный collector этим каталогом не добавляются.
