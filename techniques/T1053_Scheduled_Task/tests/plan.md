# План тестирования: T1053 Scheduled Task / Cron

## Автоматизировано

Команды запускаются из корня репозитория в окружении с dev-зависимостями.

- `python tools/check_sigma.py`: pySigma parsing и [source-scoped predicate fixtures](../../../tests/fixtures/sigma/predicates.json), включая правила этой техники; выполнение Sigma в SIEM не проверяется.

Эти проверки подтверждают поведение перечисленных fixtures. Они не измеряют эксплуатационные TPR/FPR и не доказывают полное покрытие техники.

## Следующий ручной/лабораторный этап — не выполнен

1. В Windows-стенде создать инертную задачу и сохранить 4698/106. Сравнить обычный путь действия и пользовательский/temp путь; факт создания задачи не равен вредоносному закреплению.
2. Для Linux настроить write-only audit watches с ключом cron_write и объединение SYSCALL/PATH по serial. Сохранить успешную write-class операцию, обычное чтение и отказ в записи.
3. Проверить нормализацию path/key/success. Read-only доступ и success=no не должны проходить текущий Sigma; success=yes при write intent ещё не доказывает изменение содержимого.
4. First-seen и анализ содержимого cron требуют отдельной реализации. После этого проверить baseline для deployment/RMM и редактирования cron администратором.
