# План тестирования: Service Execution (T1569.002)

## Автоматизировано

Команды запускаются из корня репозитория в окружении с dev-зависимостями.

- `python tools/check_sigma.py`: pySigma parsing и [source-scoped predicate fixtures](../../../tests/fixtures/sigma/predicates.json), включая правила этой техники; выполнение Sigma в SIEM не проверяется.
- `python tools/check_network.py`: pinned Suricata 8.0.4, загрузка правил и [синтетический PCAP replay](../../../tests/fixtures/network/cases.json) с ожидаемыми SID и количеством алертов; нужен Docker.

Эти проверки подтверждают поведение перечисленных fixtures. Они не измеряют эксплуатационные TPR/FPR и не доказывают полное покрытие техники.

## Следующий ручной/лабораторный этап — не выполнен

1. Собрать обезличенные 7045 и Sysmon 17/18 из изолированного стенда для тестового сервиса, штатного RMM/deployment и легитимного PsExec. Сопоставить ServiceName, ImagePath, процесс и пользователя.
2. Для SMB2 сравнить CREATE имена PSEXESVC, unrelated pipe и похожие prefix/suffix имена. Native PCAP replay уже проверяет эти синтетические случаи; raw-name эвристика не подтверждает создание pipe или запуск службы.
3. Проверить ложное совпадение для одноимённого обычного файла и доступность незашифрованной SMB-телеметрии. Зашифрованное SMB этим сетевым правилом не покрывается.
4. Перед проверкой Hunt реализовать его адаптер. Связь сетевого имени с 7045/process execution требует отдельной корреляции; подтверждение выполнения строится по хостовым данным.
