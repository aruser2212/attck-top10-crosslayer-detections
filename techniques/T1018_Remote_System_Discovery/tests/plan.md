# План проверки DET-WIN-T1018-DOMAIN-VIEW-001

Предикат: Запуск `net.exe`/`net1.exe` с отдельным `view` и текстом `/domain:…`. После двоеточия требуется хотя бы один символ, отличный от пробела/таба; имя домена не валидируется.

Ожидания заданы вручную в [manifest](../../../tests/fixtures/sigma/predicates.json), suite `89c24b29-3726-4e2e-b663-cc98ca5b8b54`. Поле `match` относится к Sigma-предикату; `profile_valid` и `outcome` отдельно описывают контракт process-v1. Ни одна строка команды при тестировании не исполняется.

| Группа | Ожидание |
|---|---|
| Поддержанная форма команды | Кандидат с исходным event ID и process GUID |
| Регистр, ASCII-пробелы и табы в поддержанных позициях | Указанное в fixture совпадение |
| Авторизованная активность с теми же условиями | `benign_candidate`, совпадение сохраняется |
| Другой executable, близкие суффиксы и другая операция | `nonmatch` |
| Отсутствующие Image/CommandLine | Sigma nonmatch; строгий runtime отклоняет профиль |
| Кавычки и формы вне явного покрытия | Результат фиксируется отдельно, полного argv parsing нет |

Чистое `net view /domain`, просмотр конкретного `\\host`, LDAP/PowerShell discovery и другие способы перечисления не входят в этот предикат. Ответ сети и успешность перечисления не наблюдаются. Кавычки не разбираются: `/domain:""` остаётся текстовым кандидатом, несмотря на пустой аргумент после argv-разбора.

Проверить `make check`, затем общий finite process-v1 replay на Elasticsearch Basic: маленькие страницы, точные ожидаемые rule/event IDs, immutable retry и XML → CLI. Native сравнение выполняется на одних входных записях; не заменять ручные ожидания результатом самого детектора. Лимит, неполное чтение или некорректный профиль должны завершать проход ошибкой.

Статусы и фактические результаты — в [отчёте](../../../docs/validation_report.md). Для operational precision нужны независимые labels и репрезентативная рабочая телеметрия; synthetic fixtures не устанавливают вредоносность совпадения.
